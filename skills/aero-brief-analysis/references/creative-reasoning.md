# AERO 创造性推导与工作流维护标准

版本 1.0 · 2026-10-09。用于本套工作流 P0–P7，与各阶段任务标准共同执行。本文件维护跨阶段原则，阶段 Skill 不另造冲突规则；它是团队工作约定，不是已验证的行业通则。

## 公司工作的原则

交付独特且回应客户需求的作品，让客户看到原先没有看到的问题或可能性。商业价值由本案需求定义，可以是品牌记忆、商品吸引、传播或行动，不强制所有项目以即时销售衡量。

每个项目同时完成客户任务与方法验证。复用输入、判断方式、交接和验收，不复用上个项目的洞察、主张或故事。不把一次中标、模型赞同或客户喜欢当作普遍有效的证明。

## 发现可以跳跃，判断必须说明依据

事实准确不意味着创意只能逐句演绎。允许先提出意外解释、问题重定义、审美选择或品牌立场，再回查依据、替代解释、任务相关性与品牌资格。不要求每页有新观点，也不让研究替先入为主的创意找理由。

分开记录四类内容：
- 事实与观察：发生了什么，在哪个时点、市场、对象中观察到，来源是什么。
- 解释假设：为什么可能发生，其他原因是什么，什么发现会改变判断。
- 品牌立场：品牌选择赞同或反对什么；检验任务、产品、文化与表达关联，不假装人人已经这样想。
- 表达装置：类比、夸张、倒置、虚构情节；检验理解、趣味和品牌作用，不把虚构故事当效果证据。

“有用”不是表达自由的敌人；“大胆”也不是否认事实。概念阶段按项目约定后置资源限制，进入执行承诺时再核实。不能由一个项目允许后置预算，推导所有项目都可以忽略预算。

## 如何提出新问题

按题目选用，不要求凑齐：反事实（拿掉一个条件会怎样）、因果倒置（结果能否成为起因）、视角与角色互换、尺度或时间变化、类比迁移、挑战默认评价标准。

逻辑学帮助识别前提、替代解释与因果跳步；心理学帮助提出可能的行为机制；文学、数学和生命科学可以改变视角与构造方式。引用具体理论或研究时核实原始出处和适用范围。类比只负责打开问题，不负责证明消费者动机。

最小记录只需四句：原先怎样理解 → 新解释是什么 → 哪些材料使它值得考虑 → 若成立，会改变什么选择。解释可能共存，不强行编造两种人之间的“内心矛盾”。

## 各阶段的产出与交接

| 阶段 | 输入 | 方法与产出 | 验收与下一步 |
|---|---|---|---|
| P0 任务确认 | 原始 Brief、附件、最新决定 | 一句话任务确认，按需附任务与目的表、关键待确认；六项作为内部检查；把要做、注意、表达什么交给 P1 | 准确覆盖委托；有独立判题但不预选口号或故事；改客户目标需确认 |
| P1 研究取证 | 当前任务卡与任务编号 | 覆盖自己、品牌、产品、竞争、市场、人群；材料关联任务；同步记录发现、解释、反例和会改变的判断 | 不以资料数量代替覆盖；可补查、条件性交接或建议回 P0，不强制研究得出一个统一心理 |
| P2 洞察与机会 | 证据及缺口、品牌能力 | 比较不同解释，提出新问题定义；分别标注人群洞察假设、品牌立场或传播机会 | 不必以心理矛盾为唯一入口；经验判断可检验、价值立场有品牌理由；无合格洞察可以交机会，不硬编 |
| P3 策略选择 | 任务、洞察或机会、证据状态 | 比较实质不同的解决路径；写清影响谁、改变什么、凭什么、放弃什么，以及作品如何分工 | 选择须有理由，数量随题目；共同评价任务，不能给偏爱路线更宽松的标准；定主逻辑不等于定拍法 |
| P4 核心创意 | 创意简报、策略状态 | 区分主张、Big Idea、表现手法与广告语；给出具体动作、转折、品牌商品作用及代表样本 | 口号响亮不等于有创意；实际作品须有观看理由；拿走长篇解释后仍能判断内容 |
| P5 执行传播 | 所选方向及条件 | 各触点承担不同任务，资源、预算、排期、评价方法有对应关系 | 不把所有项目变成互动挑战；无资源确认不写已落实，无效果数据不写已实现 |
| P6 提案交付 | 上游有效判断与作品 | 按客户理解与决策顺序组织页面，而非照 P0–P5 工作日志排版 | 每页注明内部角色：设问、依据、判断、取舍、揭晓、作品、承接或总结；说明为何接下一页，可跳叙但不偷换事实 |
| P7 复盘维护 | 提案反馈、执行记录、结果 | 分开记录采用、执行与效果；把能复用的改进写回所属节点 | 新规则替代冲突旧规则；注明试用范围与未验证部分，不给每次失误新增永久手续 |

## 轻量记录与自动维护

出现跑偏、听不懂、推导不对、空泛或重复犯错时，读取并执行 [对话纠错机制](dialogue-correction.md)：定位出错层，保留有效内容，撤回错误判断，用原批评复查修订稿。“继续”不自动批准相邻假设或下一阶段；具体纠正优先于早先笼统同意。规则不新增每轮表单。

优先沿用项目现有 Markdown 和看板数据，不另起重复台账。一个节点只保留必要信息：当前输入版本、关联任务、事实/假设/立场类型、当前判断、依据与反例、下一步、状态、变更原因与受影响稿件。没有必要每次把所有字段展示给用户。

用户认可的方法在同一轮完成：修改通用节点和实际 Skill 入口 → 消除相冲突旧规则 → 更新项目应用 → 更新项目登记与看板 → 重建页面 → 检查入口、链接、状态和首屏。没有完成时说明哪层未同步，不把聊天中的同意当作文件已更新。

上游重启不自动作废真实证据：事实可重用但需核对时点与范围；解释、策略、故事和提案的采用状态重新审查。旧稿后台留存，首页和当前阶段导航只显示当前有效判断。旧地址打开时需提示历史状态并指向当前入口。

主页只给当前结论、当前阶段和下一步；详细方法、依据、分歧及历史折叠或另页。未核实的建议标为建议，不能为了“直接可用”删除实质不确定性。

## 哪些自主处理，哪些需要确认

可自主处理：检索、核对、整理证据、提出与淘汰候选解释、修订措辞、消除重复、更新已同意的方法、标记旧稿影响、重建与验证看板。条件探索可以推进，但不自行升级为批准。

需要用户或客户确认：改变客户目标或交付范围、重大优先级取舍、最终策略/创意推荐的采用、对外提交，以及实际资源、费用、授权或执行承诺。已有明确授权不重复询问；多智能体按当次授权规则调用。

## 本版改变了什么

2026-10-09：依据用户要求，把创造性推导前移到任务、研究、洞察与策略；将“逐步必然推出”改为“大胆发现、明确连接并检验”；把心理矛盾由唯一入口改为可选入口；加入提案叙事与内部工作过程分离；明确方法须写回 Skill、项目与看板。具体项目的主张和故事不进入通用默认值。

验证状态：本轮完成文档与入口一致性检查后方可报同步完成；跨项目效果仍需后续真实项目检验，不承诺方法能自动产生优秀创意。
