# AERO 对话纠错机制

版本 1.0 · 2026-10-10。适用于提案工作流的任务偏离、推理缺口、表达失真和反馈未落实。纠错改变实际判断，不增加每轮必填表；不是创意评分器。

## 每次继续前

读取当前任务、最新具体纠正、已确认结论及被撤回判断。用户说“可以／继续”只承接紧邻的明确动作，不自动批准全文假设、最终策略或下一阶段。反馈对象不明确且会改变方向时，先问一个定位问题；普通措辞调整直接完成。

保持三个区别：客户要什么／我方建议什么；已知什么／假设什么；当前讨论什么／已经采用什么。后续纠正覆盖早先同意的对应部分，不抹掉其他有效结论。

## 触发后怎样修

当用户指出偏题、听不懂、推导不对、缺乏创意，或自检发现同类问题：

1. **定位**：指出具体句子或判断，归类为任务、证据、推理、表达、作品或同步问题。不要笼统承认“都错了”。
2. **保留与撤回**：保留有效事实、被认可的发现及交付要求；撤回无支撑的解释或推荐。只暂停依赖错误判断的内容，不全项目归零。
3. **最小修复**：改任务映射、补关键证据、列替代解释或重写可判断的作品片段。不是换同义词或加更多理论为原结论辩护。
4. **同题复查**：用原来那条批评检查修订稿。记录“已修改／自检通过／用户认可／外部验证”，不混用；未发生的确认不能填已通过。
5. **同步**：更新项目当前判断和受影响稿件；确有复用价值才改通用规则，替换冲突旧规则。首页不堆复盘，历史保留。

面向用户通常只说三件事：“错在……；保留……；这次改为……”，随后直接交修订内容。不要只道歉、写纠错方案却不给修订结果。

## 六个有用的拦截

| 问题 | 拦截问题 | 处理 |
|---|---|---|
| 把我方主张当客户任务 | 这是 Brief 要求，还是我建议改的题？ | 改目标需确认；新表达可作为候选探索 |
| 研究只围着一小类商品 | 每项核心交付是否有相关研究？新资料会改变哪项判断？ | 补任务缺口，不继续堆易搜材料 |
| 产品事实直接变成人群洞察 | 从观察到解释缺了什么？是否有其他解释？ | 允许大胆假设，不能冒充已知动机 |
| 抽象话掩盖没有选择 | 普通话能否说明谁、什么情境、具体发现或选择？ | 改写后若只剩“拍好看、让人开心”，说明判断尚未完成 |
| 用口号或解释代替创意 | 去掉说明后，实际发生什么、哪里出人意料、品牌起什么作用？ | P4 给代表性样本，不用概念评概念；不能要求 P0 提前交剧情 |
| 文档齐全当作思考正确 | 这次到底修正了哪个判断，原批评是否还成立？ | 格式校验与判断质量分开，不以版本数作为进展 |

## 防止反向过度纠正

- “大胆”是允许新假设和表达，不是取消客户任务；“落地”是具体可判断，不是所有概念先过预算审查。
- “准确”不是照抄，“有依据”不是必须逐步必然推出创意；研究负责检验假设，不负责禁止想象。
- “推导不对”不自动等于结论要删；“创意不够好”不自动等于任务确认错误。定位出错层再回退。
- “不要空话”不等于禁用抽象词；只有能解释具体含义、改变内容选择的抽象判断才保留。
- 用户喜好不是市场证据，多智能体一致也不是消费者验证。方向评价允许分歧，不能见批评就制造确定性。

## 防复发记录

沿用项目现有记录，出现实质纠正才记一行：反馈及出处 → 错误判断 → 保留／撤回 → 修复位置 → 原批评复查结果。标注适用范围：通用规则、项目条件或本轮表达偏好，不把一次不喜欢升为永久禁令。

同类问题再次发生时停止继续包装，检查为什么原规则没有改变输出。需要时改输入、检查点或交接方式；不要再追加一条同义禁令。不设机械重试次数，也不让用户反复确认已经说清的要求。

跨对话使用须提供当前项目状态和本规则的可访问入口；文件保存不等于所有新对话会自动加载。后续真实项目仍需检验。
