# AERO Proposal Workflow

## 从 Brief 到提案的 P0–P7 工作流

**由 AERO Creative / 艾瑞创意整理。** 面向品牌、广告、整合营销和内容项目，把客户任务、研究证据、洞察与机会、传播策略、核心创意、执行和提案连接起来。

这是可以直接阅读、复制模板、交给 AI 辅助使用的方法库。无需 API Key、安装依赖或注册服务；它不会自动生成经过客户批准的完整方案。

[完整工作流](WORKFLOW.md) · [快速使用](USAGE.md) · [空白模板](TEMPLATES.md) · [虚构示例](EXAMPLE.md) · [English](README.en.md)

## 它帮助解决什么

- Brief 有很多要求，却说不清每项交付分别要解决什么。
- 收集了大量资料，研究结论仍与策略没有联系。
- 把产品卖点、消费者假设或漂亮口号当作洞察。
- 几条策略只是换标题，作品需要长篇解释才能成立。
- PPT 按内部工作顺序展开，客户看不到问题、判断与作品的关系。

## 八个阶段

| 阶段 | 核心问题 | 可用产出 |
|---|---|---|
| P0 任务确认 | 客户到底委托什么，各项交付为什么存在？ | 一句话任务确认、任务与目的表 |
| P1 研究取证 | 哪些未知会改变方案选择？ | 任务对应的证据、解释与缺口 |
| P2 洞察与机会 | 有什么值得检验的新解释或品牌立场？ | 洞察假设／传播机会／品牌立场 |
| P3 传播策略 | 选择靠什么说服，放弃什么？ | 路线比较、推荐与回退条件 |
| P4 核心创意 | 实际发生什么，品牌和产品怎样使它成立？ | 创意方向卡与代表作品样本 |
| P5 传播与执行 | 各触点、资源、预算与排期怎样接起来？ | 执行方案与待落实项 |
| P6 提案与交付 | 客户为什么愿意接受这个判断与作品？ | 按决策顺序组织的提案 |
| P7 复盘与更新 | 哪些被采用、执行、验证，方法应怎样改？ | 结果记录与可复用修正 |

阶段可以往返。纯适配任务走简版；有授权的条件探索可以继续。客户确认、事实验证与执行授权分别记录。

## 五分钟开始

1. 阅读 [WORKFLOW.md](WORKFLOW.md)，判断当前停在哪一阶段。
2. 复制 [TEMPLATES.md](TEMPLATES.md) 到自己的私有项目目录，填写 Brief 来源、任务、当前状态。
3. 按当前阶段使用对应 Skill，或将相关 Markdown 提供给支持文件阅读的 AI。示例提示词见 [USAGE.md](USAGE.md)。
4. 用 [EXAMPLE.md](EXAMPLE.md) 检查事实、假设和作品是否被正确区分。

不要把真实客户资料提交到本公开仓库。

## 四个阶段 Skill

- [aero-brief-analysis](skills/aero-brief-analysis/SKILL.md)：P0，理解委托与任务确认。
- [aero-research-evidence](skills/aero-research-evidence/SKILL.md)：P1，研究设计与证据判断。
- [aero-insight-development](skills/aero-insight-development/SKILL.md)：P2，洞察、机会与 P3 交接。
- [aero-creative-concepts](skills/aero-creative-concepts/SKILL.md)：P4，核心创意与代表样本。

P3、P5、P6、P7 的方法和模板在主工作流中；本版没有声称提供八个独立 Skill。四个 Skill 有相互引用，使用时保留完整 `skills/` 目录结构。

## 方法原则

发现可以跳跃，判断必须说明依据。事实、解释假设、品牌立场、虚构表达分开；没有合格人群洞察时，可以交传播机会与缺证清单。复用判断方法，不复用上个项目的结论。

公开版 v1.0.0 整理自工作流 v1.16 与共享规范，保留方法并清理真实项目内容。当前发布完成的是文档与结构整理；跨项目成效仍需检验，不承诺中标、销量或自动产生好创意。
